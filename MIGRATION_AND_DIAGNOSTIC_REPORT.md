## 3. Migration Milestones & Execution

### Phase 1: Archive Analysis & Verification
- **Input File:** `ea68b889-8005-4661-86ee-dc8738703ed2_261006.backup` (~40.02 MB).
- **Inspection:** Inspected header magic bytes (`PGDMP`), confirming a compressed custom binary dump generated by `pg_dump -Fc` under PostgreSQL 17/18.
- **TOC Audit:** Analyzed the table of contents using Docker `postgres:17 pg_restore -l`. Confirmed complete table definitions, sequences, triggers, and Row Level Security (RLS) rules.

### Phase 2: Database Restoration
- Uploaded the dump to VPS (`/tmp/backup.dump`) and transferred into the active database container:
  ```bash
  docker cp /tmp/backup.dump mayax-supabase-pixbhb-db-1:/tmp/backup.dump
  docker exec -i mayax-supabase-pixbhb-db-1 pg_restore -U postgres -d postgres \
    --clean --if-exists --no-owner --no-privileges /tmp/backup.dump
  ```
- **Audited Restored Data Counts:**
  - `auth.users`: **25 accounts**
  - `leads`: **3,682 records**
  - `purchases`: **3,631 records**
  - `wallet_transactions`: **3,749 records**

  - `autopay_settings`: **4 records**

### Phase 4: Schema Alignment for 4-Role System
Because commit `c6dccce` added a 4-role user model that was newer than the dump, the following database updates were applied:
1. Created `provider_profiles`, `normal_user_profiles`, and `provider_payouts` tables with RLS policies.
2. Altered `public.leads` to add `listed_by_id`, `listed_by_role`, `review_status`, and `review_notes`.
3. Added stored generated columns on `leads` for backward/forward compatibility:
   - `full_name`: `TRIM(COALESCE(first_name, '') || ' ' || COALESCE(last_name, ''))`
   - `lead_email`: `email`
4. Refreshed PostgREST cache (`NOTIFY pgrst, 'reload schema'`).
